# 测试大纲

> 版本：v1.9 · 状态：测试策略草案；执行记录见文末

## 1. 测试目标

验证用户能否在需求由人确认的前提下完成从项目创建、需求分析、任务追踪、角色协作到文档持久化的基本闭环；验证项目隔离、版本恢复和模型不可用时的边界表现。

## 2. 测试范围

- 项目创建、切换、状态读写与隔离；旧版默认空间来源提醒及 Agent 上下文的数据证据警示。
- 项目创建向导表单、九类初始文档、空需求/任务基线、初始描述持久化和“不自动调用模型”的引导说明。
- 总览准确区分待开始、进行中、待评审、阻塞、已完成以及服务端连接状态。
- 首页树形 Roadmap 阶段、需求、任务和文档节点；点击节点应显示当前状态、责任角色、验收/阻塞信息和最新项目事件。
- PDT 流程节点顺序、瀑布/敏捷/混合模式说明、角色入场条件和各阶段交付文档链接。
- 项目并行上限 1–32、单任务串/并行开关、进入“进行中”的容量校验、串行互斥和降低上限的边界。
- SSE 新事件可达路线图详情；断开自动重连；Agent 图步骤进度与项目领域事件可区分；事件内容不泄漏消息正文或密钥。
- 待裁决需求/决策主动弹窗；关闭后不循环打断；新待办可再次提示；弹窗不替用户提交裁决。
- PDT 聊天、角色聊天和群组同步；模型已配置/未配置/调用失败。
- 群组和角色消息的 Markdown 标题、列表、代码块、表格、行内格式、图片及安全链接排版；同时用历史字符串、对象、文本块数组和旧会议 JSON 载荷覆盖归一化；原始 HTML 不执行，危险链接协议不生成可点击链接。
- 需求列表/必读摘要/Roadmap 节点标题、描述、证据和阻塞文本中的 Markdown，以及嵌套列表和换行排版。
- 候选需求、Kano 类别/证据/置信度、用户裁决、拒绝/补充分析。
- 未批准需求任务门禁及批准后任务追踪。
- 用户批准后自动 PM 拆解队列的持久化、角色任务生成、验收标准、文档/群组同步、重启接管、模型缺失等待和失败重试。
- 退回补充分析后原需求返回待裁决，历史、理由、需求包/PRD 内容、群组和快照保持一致；不产生重复需求或任务。
- 任务合法/非法状态迁移、负责人权限、缺少验收标准时禁止完成、完成/阻塞说明、项目群/审计/设计和测试文档快照。
- 汇报关系完整性、循环拒绝、所有角色房间单聊及结果群同步。
- 开发模式持久化、任务按需求/负责人筛选、CSV 与 Markdown 项目包导出。
- 对待裁决需求进行确认、拒绝、修改后再议、挂起待证据；核验必填理由/字段、DRAFT 到 REQ v1 转换、修改历史、文档/群消息/事件同步；除确认外不得生成任务。
- 服务端断开期间确认、拒绝、修改或挂起后恢复服务，队列自动补同步；批准前不伪造基线/任务；重复 action 不重复改版本，冲突操作不覆盖服务端状态。
- 文档骨架、正文写入、版本快照、历史预览和恢复。
- 项目记忆创建/去重/来源与对象关联、Agent 只能创建待核实假设/风险、人工确认/取代门禁、角色上下文筛选及 Markdown 项目包导出。
- 需求证据等级展示与导出；AI 建议边界文案；E0–E4 仅作为来源强度建议的理解度评审。
- 项目记忆版本递增、审阅人、变更摘要长度上限、旧数据基线迁移和导出历史。
- 记忆一跳追溯中的直接关系、结构化 fact ID 引用、文档编号命中、间接同需求关系区分；聊天/角色 transcript 不得作为引用证据；不存在目标时返回明确空态。
- 需求追溯 API/UI 的裁决、决策、记忆、任务和文档链路，以及无关联空态。
- AI 项目决策建议的用户审阅：必填理由、采纳/拒绝/搁置、版本和历史、群消息/文档/事件一致性；重复同裁决幂等、冲突裁决被拒绝，且不自动批准需求或建任务。
- 必读摘要更新准确性、未核实信息标记及单独 Markdown 导出。
- 旧浏览器提交不含新字段或空字段的整体状态时，已有事实、需求计划、项目决策、会议、团队配置（含角色 Runtime）和 PM 自动任务仍保留；不同用户并行编辑的一般状态冲突仍需单独验证。
- 会议主题/议程配置与项目默认议程持久化；手动/自动会议输入上下文、参与者与 transcript、结构化纪要、裁决请求、交付顺序、项目群和文档摘要同步。
- 会议 AI 行动建议需关联已确认 REQ、有效交付角色与验收标准；未确认不产生任务；确认后只建一次，事件、群组、文档和关联任务一致。
- 会议角色/PM 调用失败和异常清理；`meetingLive` 复位，状态/错误可见；模型未配置时不创建虚假会议。
- 角色数量/提示词变化后的 Agent 更新与职责工具边界。
- 敏感配置、本地数据目录和部署/备份流程。
- 完整项目 JSON 导出包含状态、全部项目事件和文档版本快照，不包含服务端密钥；删除项目需精确名称确认、默认项目不可删、其他项目关联表记录均被清理。

## 3. 测试层级与方法

1. **单元/组件**：Kano 输入归一化、状态迁移、任务门禁、任务编号、文档比较/快照和恢复版本、角色缓存键、会话历史裁剪。
2. **API 集成**：各 FastAPI 路由的输入边界、HTTP 错误、项目 ID 隔离、事件与持久化一致性。
3. **Agent 契约**：角色只能使用授权工具；Agent 不可批准需求；工具输入不充分时返回“待分析/待确认”；文档更新先读取再完整写入。
4. **端到端 UI**：新建项目、需求裁决、文档查看/恢复、单聊/群聊和会议控制的主要用户路径。
5. **可靠性/安全**：应用重启后状态仍在；模型超时/失败不会伪造成功；未配置模型时提示明确；密钥不出现在响应、前端或日志；外部网络接口未授权访问时不可被误认为安全部署。
6. **可用性评审**：短时间理解当前阶段、待决策、任务阻塞和文档变化；读屏/键盘导航及窄屏布局。

## 4. 关键验收场景

| 场景 | 前置条件 | 预期结果 |
|---|---|---|
| 新建第二个项目 | 已有一个项目和业务数据 | 新项目需求、消息、任务、文档独立；原项目数据不变 |
| 缺乏证据的魅力型候选 | 用户只提交功能主张，未提供目标人群证据 | 状态保留分析/待确认，解释缺口，不宣称分类已验证 |
| 批准前尝试建任务 | 候选需求尚未批准 | Agent 工具和 API 均拒绝创建正式任务 |
| 用户批准需求 | 候选需求已分析可审阅 | 记录用户裁决并建立关联拆解任务，更新文档版本和事件 |
| 批准后自动拆解 | 用户已确认需求且 Deep Agents 已配置 | 队列自动运行 PM；创建至少一项带验收标准的需求子任务，更新交付文档和群消息，进度刷新到 UI；重启后接管排队项 |
| PM 拆解失败并重试 | 模型调用失败或 PM 未创建关联任务 | 父任务进入阻塞、错误与事件可见；用户重新派发后生成新的尝试任务，不改变批准裁决 |
| AI 项目记忆需人工确认 | Agent 通过工具记录假设/风险 | 条目进入待核实；角色上下文能看见状态但不得把它表述为事实；用户确认后成为当前上下文，标为取代后继续保留历史 |
| 用户退回补充分析 | 候选需求待裁决 | 原记录转“分析中”；补充结果更新原记录并重新送用户裁决，过程写入文档版本；未批准不得创建任务 |
| 任务完成/阻塞 | 任务处于可转换状态 | 无验收说明不得完成、无原因不得阻塞；事件/群组/文档版本保存同一状态变化 |
| 循环汇报关系 | 提交含 A→B→A 的团队关系图 | API 拒绝更改；已保存的项目关系仍完整且无循环 |
| 更新后恢复旧文档 | 文档存在至少两个快照 | 旧版可预览；恢复创建新版本，旧快照保留 |
| 模型不可用 | 未设置可用运行时或供应商调用失败 | 本地状态操作仍有清晰提示；不展示伪造的 Agent 结论 |
| 会议行动项需确认 | 模拟 PM 返回关联已确认需求的行动项 | 会议保存结构化行动建议但不建任务；用户确认后创建一次关联任务，重复请求返回原任务 |
| 会议建议不可执行 | PM 返回未确认需求、无有效负责人或无验收标准的行动项 | UI 显示待补充原因，服务端拒绝转任务，任务总数不变 |
| 会议部分失败 | 某角色调用失败但其他角色和 PM 返回 | 会议状态显示部分完成与错误，`meetingLive` 复位，已保存发言不丢失 |
| 本地应用关闭时到达会议时间 | 自动会议已启用 | 重启后对过期任务有明确恢复策略（当前能力需验证/实现） |
| 项目间跨 ID 请求 | 至少两个项目存在 | API 返回指定项目内容，不混入其他项目事实 |
| 待评审状态总览 | 已确认需求关联的任务均处于评审中 | 显示待评审数量和有交付项的角色，不误报项目尚未启动或没有角色协作 |
| 路线图任务节点 | 需求关联多角色任务，含评审/阻塞/已完成 | 任务按角色阶段展开在需求下；点击后可见验收、状态历史和新事件 |
| 并行容量已满 | 项目最大并行数为 1，已有一项任务进行中 | 第二项任务启动返回 409；状态不变；说明释放执行位或调高上限 |
| 串行任务启动 | 至少一项其他任务正在进行中 | 串行任务无法同时启动；已有串行任务时也拒绝启动并行任务 |
| 并行上限下调 | 进行中任务数高于目标值 | 配置 API 返回 409，既有配置和任务状态保持不变 |
| 多视图 Markdown 渲染 | 在项目方向、文档卡片/正文、需求、记忆、决策、会议、追溯和项目动态填入标题/表格/代码/任务清单 | 各视图按一致规则排版，原始 HTML 与 `javascript:` 链接保持惰性文本，代码和宽表格可滚动 |
| 首页会议摘要 | 最近会议保存有效或含未转义引号的 JSON 纪要，返回首页 | 显示转换后的摘要、交付顺序和行动建议，不把原始 JSON 包装当正文展示 |
| 每角色 Runtime 配置 | 对单角色依次选择平台、Codex、Claude Code，重开项目后查看配置 | 选择和工作区路径按项目持久化；平台选项不要求仓库路径；外部 CLI 配置必须是可访问的绝对目录 |
| Codex 外部 Runtime | Codex CLI 存在且已登录，角色选择工作区后进行安全的合成请求 | 角色从配置工作区启动，操作限制在 `workspace-write` sandbox；进度事件与最终报告可见并写入角色会话/项目群；平台 DeepSeek key 不传入子进程 |
| Claude Code 外部 Runtime | Claude Code CLI 存在且已登录，角色选择工作区后进行合成请求 | 以 `acceptEdits` 和有限 turn 数执行；成功/缺失/登录失败/非零退出/超时有明确结果，不使用 bypass 权限模式 |
| 子 Runtime 配置和错误边界 | 提交相对路径、不存在目录、文件而非目录、未知角色 provider 或未安装 CLI | 无效配置被拒绝或运行时明确报错，不静默回退到平台；原配置保持不变 |
| 旧整状态兼容角色 Runtime | 已保存 `roleRuntimes` 后提交不含该字段的旧版状态快照 | 服务端保留已保存配置，角色仍按原 provider 调度 |
| PDT 跨 Runtime 委派 | PDT 平台 Runtime 委派给一位配置为子 Runtime 的角色 | 不从内部 Deep Agents 子 Agent 偷跑；目标角色按 CLI 配置执行，报告进入角色会话和群组，PDT 可据报告继续调用平台项目工具 |
| SSE 路线图进度 | 打开阶段/任务详情并提交一个领域状态变更 | 事件经 SSE 到达，详情面板新增时间、角色和事件摘要；刷新后任务状态与 SQLite 一致 |
| 待用户裁决主动提示 | 存在待确认需求或决策 | 总览首次加载主动显示待办入口；打开详情后仍须用户显式提交裁决 |

## 5. 测试数据和环境

使用合成项目、合成需求和专用临时 SQLite 数据库；不得用客户个人信息。Agent 集成测试可用 stub/mock 验证工具契约，端到端模型测试需单独标注供应商、模型和耗费。开发/CI 与用户本地 `.data`、`.env` 隔离。

## 6. 退出标准（待确认）

产品闭环关键场景通过；阻断级/严重级缺陷为零；需求批准门禁及文档恢复没有未解释失败；项目隔离和密钥处理通过评审；模型故障路径明确。具体覆盖率、性能和可靠性门槛尚待产品试点后定义。

## 7. 未覆盖风险

完整多人并发、生产级权限、队列故障恢复、模型供应商安全评估、长时间运行、文档差异和数据迁移还需要专项方案。本文是测试计划，不是执行报告。
