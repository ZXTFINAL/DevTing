# 开发自测大纲

> 版本：v1.6 · 状态：自测清单草案；未执行状态由实际开发记录更新  
> 日期：2026-10-13

## 1. 每次代码变更

- 阅读本次变更影响的需求、接口、数据和文档；补充实现状态或待确认事项。
- Python 改动运行语法/导入检查；前端改动检查浏览器控制台和关键页面渲染。
- 确认新配置可缺省启动，错误信息可读，不输出密钥。
- 确认状态读写仍指定当前项目 ID，不意外覆盖其他项目。
- 确认新增的文档变更说明来源、版本和更新内容。

## 2. PDT / 需求分析自测

- 将用户事实、推断、建议、证据和未知项分开表达。
- Kano 结论有分类理由、置信度与证据限制；信息不足时保留待分析。
- 没有用户批准记录，不创建正式研发/测试/UI 任务。
- 用户补充或拒绝后，需求状态和相关产品文档与项目消息保持一致。
- 用户可记录拒绝/搁置及理由；已裁决需求不能重复裁决；拒绝或搁置不得创建任务。
- 离线裁决先留在浏览器队列；恢复服务后自动写入服务端并拉取最终状态，验证重复裁决与冲突裁决路径。
- 用户批准需求后确认 PM 队列状态持久化，模型就绪时自动生成带验收标准的角色任务和关联文档更新；失败时父任务标阻塞、错误可读，重试不改变用户裁决或重复成功任务。
- 确认项目记忆必须有来源；人录入的内容标为“用户提供”，AI 只能写待核实假设/风险；用户确认后才作为接受的上下文，取代记录仍保留且不再进入 Agent 上下文；导出包包含记忆与来源。
- 用超过默认上下文数量的记忆验证 Agent 可关键词检索旧条目；结果保留来源、关联编号和审阅状态，不把待核实条目当事实。
- 补充分析更新原需求而不是重复新建；提交后回到待用户裁决并更新产品包 / PRD 内容。
- 确认需求详情将 AI 分析标为“AI建议，非结论”；E0–E4 描述来源强度而非真实性结论，CSV 与项目交付包也保留证据等级。
- 确认候选项先显示 DRAFT 编号和必填分析字段；确认、拒绝、修改后再议、挂起待证据四种裁决均要求理由，修改保留前后版本，只有确认分配正式 REQ v1 并创建 PM 队列项。
- 断网时尝试裁决和修订，确认本地待同步状态可见；恢复连接后服务端编号、草稿版本、文档和群消息一致，旧浏览器快照不会复活已批准草稿。
- 新项目记忆应包含版本 1、来源等级与创建历史；审阅应递增版本、记录用户审阅人、前后状态和不超过 200 字变更摘要；历史项目迁移为 E0 且不得伪造原始来源。
- 从需求详情打开追溯链，确认显示人类裁决、决策建议、显式关联记忆、任务、相关文档与澄清历史；无关联项应明确显示空态而不是推断关系。
- 从项目记忆追溯打开引用列表，区分直接关联、显式引用和间接同需求任务；确认聊天/会议逐字内容不冒充事实证据，`FACT-001` 不误命中 `FACT-0010`。
- 在决策台分别审阅 AI 建议并填写理由；检查提议人、审阅人、时间、版本和历史，重复同一裁决不重复写入，冲突裁决被拒绝；采纳决策不创建需求或任务。
- 修改角色人数、专属提示词和汇报关系后刷新/重启项目，确认由服务端加载；非法角色、人数字段越界、超过长度限制及循环汇报关系均拒绝且原配置保持。
- 修改任一角色 Runtime 和工作区后刷新项目，配置仍可读；提交缺少新字段的旧版整状态后 `roleRuntimes` 仍保留；非法路径及缺失 CLI 明确报错，不静默回退到平台 Runtime。
- 项目记忆页必读摘要应反映当前裁决、任务、风险和待确认信息，并可导出；检查汇总不把待核实内容写成确认事实。

## 3. 角色交付自测

- 只领取与自己职责相符的任务；明确交付物、验收标准和下一步。
- 影响范围或架构的建议交给 PDT/SE/PM；给相关同事发布必要同步。
- 文档修改前读取当前版本，保留原决定和未决内容，写入完整修订正文。
- 不把 Agent 回答说成代码已经落地；报告完成时给出文件、接口、证据或测试结果。

## 4. API / 数据自测

- 空项目创建后能重开，状态和文档骨架完整。
- 保存时按文档变化生成对应版本，未变化文档不重复生成快照。
- 需求未批准时任务 API 返回冲突；批准时审计字段和关联任务正确。
- 任务按负责人/需求筛选；非法状态跳转被拒绝；没有验收标准或说明时不能标记完成；阻塞须说明原因；状态历史和相关文档正文有快照。
- 汇报关系保存可见且所有层级最后到达 PDT，循环关系被服务端拒绝；每个角色可进入独立对话房间。
- 开发方式变更重启后仍保持；项目交付 Markdown 与需求 CSV 包含当前本地状态。
- 项目选择器导出完整 JSON 并核对包含会话、事件和文档版本；确认文件不含密钥且标明不可导入恢复。删除测试项目时先导出、错误名称不删除、准确名称后清理数据；默认项目始终保留。
- 恢复快照保留旧版本并产生新版本记录。
- 模型断开、缺密钥、Agent 异常时不会丢失已保存用户消息或伪造响应。
- 会议异常后 `meetingLive`/状态可恢复或有清晰失败记录。
- 手动会议提交主题/议程；确认状态、发言、PM 纪要、裁决请求、交付顺序与行动建议均保存，项目群和交付文档同步摘要。
- 不接受未关联已确认需求、有效负责人或可验证标准的会议行动项；确认后任务反向关联会议与行动项，重复点击不重复建任务。
- 自动会议使用项目默认议程；模型缺失或 Agent 异常时给出清晰状态，不留下永远运行中的会议。

## 5. UI 自测

- 项目创建向导的必填、返回/取消、重复提交和切换路径清楚。
- 需求的状态、Kano 解释、证据和裁决按钮对应真实后端行为。
- 文档正文不会被截断或以 HTML 执行；历史预览和恢复按钮明确。
- 私聊、项目群和消息来源可辨；群同步不会让用户误以为所有私聊内容都完全共享。
- 群组消息中的标题、列表、引用、表格和代码段可读；原始 HTML 与 `javascript:` 链接保持惰性文本。
- 项目方向/摘要、文档卡片描述/正文、需求列表与详情、记忆、决策、会议、路线图节点、追溯和项目动态中的 Markdown 同样渲染；嵌套列表、任务复选框正确，版本预览与正文一致。
- 角色团队页和详情窗口显示所选平台/Codex/Claude Code；命令存在与 CLI 已登录的状态须明确区分，外部工作区路径和权限边界清楚说明。
- Codex/Claude Code 角色的直接对话和会议发言显示进行中状态；完成后角色会话与项目群有报告，失败/超时显示错误而非无限等待。
- 加载、空数据、错误和窄屏状态有说明。
- 有评审中的任务时，总览显示待评审数量和有交付项的角色；不显示“项目尚未启动”。服务端离线提示与缓存中的项目进度分开显示。
- 首页 Roadmap 按 PDT 阶段展开需求、任务和文档；点击每类节点均显示真实结构化状态，刷新/事件推送不会丢失当前节点选择。
- Agent 每个图步骤写入项目事件并通过 SSE 到达路线图；核对连接状态、断线自动重连和仅传摘要、不传模型输出正文。
- 修改项目并行上限后刷新仍保留；将任务标为串行/并行后刷新仍保留；超限/串行冲突返回明确错误并保持原任务状态。
- 存在待裁决需求/决策时总览主动提示；稍后处理可关闭；同一待办不在每次刷新反复弹窗；用户仍需进入裁决表单并显式提交。
